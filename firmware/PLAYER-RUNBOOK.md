# Плеер на XREAL One Pro: сборка, запуск, режимы

Практическая шпаргалка по всему, что собрано и проверено на устройстве
(Artosyn AR9481, ядро 4.9.38, glibc 2.25). Режим, ради которого всё делалось, —
очки работают без внешнего видеосигнала: панель чёрная, `pilot` жив, плеер выводит
картинку своим OSD-слоем.

## 1. Доступ

```
ssh -i ~/.ssh/xreal_onepro root@169.254.1.1
```

Адрес `169.254.1.1` — link-local по USB-C. Если не отвечает: `nc -z 169.254.1.1 22`
(кабель переподключали или хост уснул). Шелл на устройстве — busybox `sh`,
`timeout` в нём нет.

## 2. Сборка

Исходники: `davnozdu/xreal-one-pro-player`, сборка — GitHub Actions
(`.github/workflows/build.yml`, артефакт `xreal-miniplay-arm64`).

Ветка с текущими правками: `fix/audio-long-clips`. Сборка запускается вручную,
потому что workflow висит только на `main`:

```
gh workflow run build.yml -R davnozdu/xreal-one-pro-player --ref fix/audio-long-clips
gh run list -R davnozdu/xreal-one-pro-player --limit 1 \
   --json databaseId,status --jq '.[] | "\(.databaseId) \(.status)"'
gh run download <run-id> -R davnozdu/xreal-one-pro-player -D pa
scp -i ~/.ssh/xreal_onepro pa/xreal-miniplay-arm64/xreal_miniplay \
    root@169.254.1.1:/usrdata/tmp/hwdec/xmp<N>
ssh -i ~/.ssh/xreal_onepro root@169.254.1.1 'chmod +x /usrdata/tmp/hwdec/xmp<N>'
```

Перед копированием обязательно снять старый экземпляр, иначе `Text file busy`:

```
ssh ... 'killall -9 xmp8; sleep 1'
```

Ограничение CI: стабы libc/avutil урезаны — нет `getenv`, `strtod`, `av_frame_clone`,
`memmove`. Новые зависимости в код не тащить, параметры передавать аргументами
`strtol`.

## 3. Запуск

```
cd /usrdata/tmp/hwdec
export LD_LIBRARY_PATH=/lib:/usr/lib:/usrdata/pilot/bin
./xmp8 --hwdecode ./videosample.mp4 40 16
```

Режимы и аргументы:

| Аргумент | Смысл |
| --- | --- |
| `--demo [секунды]` | проверка вывода без видео (рисует тестовый кадр) |
| `--hwdecode` | аппаратный декодер через `libxrlinux_codec.so` (обязателен для 720p60) |
| `--yuv` | вывод YUV420p вместо BGRA |
| `<медиа>` | файл видео |
| `[секунды]` | сколько играть; `0`/пусто — до конца |
| `[lead_ms]` | подача кадра заранее, миллисекунды (по умолчанию 0) |

Плеер при старте печатает:

```
Paused Pilot (pid 504) during playback
Audio ready: stream 1, 48 kHz stereo via XREAL audio service
OLED overlay ready: 1280x720 -> 1920x1080 on both eyes (buffers=3, cached_mmz=3/3, osd90=2/2)
Playing ./videosample.mp4 (1280x720 -> 1920x1080)
```

В конце — метрики:

```
Mean milliseconds: acquire 0.0, prepare 3.0, submit 0.2
Present interval (ms): min 4.6, avg 16.7, max 18.0, spikes(>1.5x) 0/1499
Shown 1500 frames, dropped 0 late frames.
```

Запуск в фоне (чтобы SSH не висел), с логом:

```
setsid ./xmp8 --hwdecode ./videosample.mp4 40 > play.out 2>&1 < /dev/null &
```

**Обязательно после теста** вернуть пилот, если плеер убивали:

```
killall -9 xmp8; kill -CONT <pid-pilot>
ps w | awk '/[p]ilot$/ {print $1, $3}'      # состояние должно быть S, не T
```

## 4. Режим «нет внешнего видеосигнала»

Подробно — в `firmware/DISPLAY-OFF.md`. Коротко: нужное состояние даёт сброс
Type-C/DP-PHY (в `dmesg`: `coconut_typec_reset_assert` → `coconut_dprx_init_phy` →
`coconut_typec_reset_deassert`), после него хост перестаёт держать дисплей, а питание
и USB живы. Признак в логе плеера — `DP get 0, 0 failed, dp vsync 0`, при этом кадры
идут. Возврат — переподключить кабель.

## 5. Звук

Сервис `NRAudioPlayWavFile` принимает файл только при трёх условиях:

1. канонический PCM WAV: тег `01 00`, fmt-чанк 16 байт (`WAVE_FORMAT_EXTENSIBLE` от
   ffmpeg проглатывается молча, `return[0]` и тишина);
2. файл лежит **в `/tmp`** (в `/usrdata/...` тоже «успешно», но без звука);
3. `pilot` остановлен на время воспроизведения.

Сервис не склеивает клипы — перезапускает воспроизведение на каждом файле, на стыке
теряются десятки миллисекунд. Поэтому клип в плеере — 20 с (`CLIP_MS` в
`src/xreal_audio.c`), провал раз в 20 секунд вместо раза в секунду.

Проверка звука без плеера:

```
/usrdata/tmp/hwdec/audioplay /tmp/xa/10.wav 10 0     # один клип
/usrdata/tmp/hwdec/audioplay s /tmp/seq 8 960        # последовательность
```

Как сделать корректный клип из видео:

```
ffmpeg -y -i in.mp4 -t 10 -vn -ac 2 -ar 48000 -f s32le /tmp/raw.pcm
python3 -c "import wave;raw=open('/tmp/raw.pcm','rb').read();w=wave.open('/tmp/clip.wav','wb');\
w.setnchannels(2);w.setsampwidth(4);w.setframerate(48000);w.writeframes(raw[:48000*2*4*10]);w.close()"
```

## 6. Что сделано и что нет

Исправлено и подтверждено на устройстве:

- аппаратный декод: 900 кадров / 0 пропусков на 720p60 (софт-декод не тянет: 254 % CPU,
  521 кадр / 308 опоздавших);
- звук: клипы 20 с вместо 960 мс (1799 кадров, 2 клипа за 45 с, «звук идеальный»);
- кадр готовится (масштаб и композиция) до своего дедлайна — из критического пути ушла
  подготовка 2.4–3.0 мс и отправка 4.2 мс, разброс интервала сжался с 24.8–32.9 мс
  до 18.0 мс;
- режим без видеосигнала: панель чёрная, пилот отвечает, вывод плеера работает.

Не устранено: остаточное дрожание картинки на панорамах (особенно сверху вниз).
Что уже проверено и не помогло:

| Попытка | Результат |
| --- | --- |
| частота слоя 90 → 60 → 120 Гц | без изменений |
| ожидание тика дисплей-сервиса (`NRVsyncStart`) | тики пропадают при остановленном пилоте, частота плавает 121.9–123.3 Гц |
| программный масштаб вместо скейлера VO | без изменений (и `prepare` дороже: 8.3 мс) |
| подача кадра заранее на 8 / 16 мс | без изменений |
| слой 1920×1080 без масштабирования | слой выделяется, но панель ничего не показывает |
| пул декодированных кадров в RAM | не собралось: в стабах CI нет `av_frame_clone` |

Измерено: панель тактуется ~121.9 Гц (интервал 8.21 мс), контент 60 к/с — отношения
не целые (2.03 тика на кадр), поэтому идеально равномерный показ на этой развёртке
недостижим без ретайминга контента или перевода панели на 120.0 Гц. Следующий шаг,
если продолжать: пул кадров с собственной копией пикселей (без `av_frame_clone`) и
проверка, забирает ли сервис буфер по своему тику.

## 7. Ловушки

- `kill -9` плеера оставляет `pilot` в состоянии `T` — картинка мигает, кнопки не
  работают. Лечится `kill -CONT <pid>`; сторож в плеере пока не сделан.
- `voctl disable 0` (или `0x1000`) ломает OSD-канал: `enable_osd_vo_layer: enable vo0
  channel failed`, лечится только перезагрузкой. Не трогать.
- Процессы, залипшие на `/dev/vdec0` в состоянии `D`, не убиваются — только reboot.
- Ручной вызов `AR_MPI_VDEC_*` из своего процесса залипает (CUSE `/dev/vctrl`,
  ioctl `0xc018410f`) — работать только через `libxrlinux_codec.so`.
- Логи `XrlinuxCodec` пишутся всегда и быстро растут; чистить `/usrdata/tmp/hwdec/*.out`.
- `/tmp` — tmpfs 119 МБ; клипы 20 с занимают ~7.7 МБ каждый, при экспериментах их надо
  убирать (`rm -rf /tmp/xreal-audio-*`).
